# DCMenu 中文注释教学菜单

首次启动会在 `plugins/DialogCanvas/examples/menus/` 生成十份完整 YAML，之后启动只补齐缺失文件，不覆盖已有教学文件。
这是教学原件目录：文件生成本身不会自动加载菜单、不扣款、不执行命令，也不修改玩家数据。

## 十份示例分别是什么

| 编号与菜单 ID | 用途及实际影响 |
| --- | --- |
| wiki_01_notice | 最小提示菜单，只展示文字并关闭 |
| wiki_02_confirmation | 确认/取消菜单，确认按钮只发消息 |
| wiki_03_navigation | 多列导航，跳转到前两份菜单 |
| wiki_04_inputs | 勾选、文字、数量滑块、单选四种输入 |
| wiki_05_text_icons | 图标、颜色、多色渐变、悬浮说明及正文物品展示 |
| wiki_06_conditions | 权限、PAPI、玩家数据、数字和文字条件，以及嵌套条件组 |
| wiki_07_commands | 玩家、临时 OP、控制台三种身份执行命令，需管理员测试 |
| wiki_08_shop | 橡木原木真实买卖：买入每个16、卖出每个8游戏币，含限购/冷却 |
| wiki_09_limits | 五种限购周期、冷却；点击会真实发放石头 |
| wiki_10_player_data | 初始化、修改和检查自己的 wiki.* 业务数据 |

这十份是教学菜单集合，其中第08份是买卖商店，并非十个不同的商店。

## 推荐：在网页按需导入

1. 控制台运行 `dcmenu editor`，在服务器电脑打开输出的本机地址，登录编辑器。
2. 点击“导入 YAML”，选择本目录对应文件。核对 ID、标题、校验结果和依赖说明。
3. 确认进入草稿后点击“校验”，再“保存”；等待显示保存完成。
4. 游戏管理员运行 `/dcmenu open wiki_01_notice`，或控制台运行 `dcmenu open wiki_01_notice 在线玩家名`。
5. 第03份引用第01/02份，请先导入01、02，再导入03。全部安装时按01→10顺序进行。

网页与游戏在不同电脑时，127.0.0.1 指的是服务器电脑；编辑器不提供公网访问。

## 也可以用控制台导入

将选中的教学 YAML 复制到插件的 `plugins/DialogCanvas/menus/` 目录，保留文件名和文档内 id 一致。
不要覆盖已有同名菜单。随后控制台运行 `dcmenu reload wiki_01_notice`，确认成功再打开。
仅编辑 examples/menus 中的教学原件不会影响已保存菜单；正式手动编辑入口是 plugins/DialogCanvas/menus。
YAML 修改失败会保留上一份可用菜单，请按具体错误修改，不要直接修改正式 JSON 或同步基线。

## 交易、依赖与注释

- 第08份会真实扣款、发货、收物品和充值，需要 Vault 兼容桥与真正的经济提供者；先用测试账号和小额余额。
- 第06份的 PAPI 条件需要 PlaceholderAPI 及对应扩展；普通文字和其他示例不因此依赖 PAPI。
- 第06份的玩家数据检查可先用第10份初始化。第07份的 OP/控制台命令、第09/10份同样有实际影响。
- 网页输入 `$(amount)` 等表达式时，amount 必须对应本菜单的输入 key。PAPI 的 `%...%` 需要实际安装的扩展。
- 正式数据写入 `data/menus/<id>.json`，手动入口 `menus/<id>.yml`；使用现有 revision 和 YAML 冲突保护。
- 插件重新导出正式 YAML 会规范化排版并丢弃手写注释。这里 examples/menus 下的原件保留详细注释，不会被网页保存覆盖。
- 不支持直接导入 KaMenu 或其他插件格式，不凭注册名自动接入其他插件的私有物品。

更新插件不会覆盖你修改过的教学文件。需要恢复某个教学原件时，先备份并移走该文件，再重启补齐；不要删除正式菜单或玩家数据。
