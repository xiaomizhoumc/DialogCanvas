# 04.7 玩家数据、限购、冷却与事务

[返回 Wiki 首页](../README.md) · [项目入口](../../../README.md)

> 适用：DialogCanvas 1.0.0，Paper 26.1～26.3 系列（构建范围见最终验收）；核对日期：2026-10-16。

**前置知识：** 条件和动作基础；了解真实业务影响。

## 玩家业务数据

`player_data_set` 写 JSON 值，`player_data_increment` 计算数值增量；key 如 `wiki.count`，不是文件路径。当前数据按 UUID 存在 data/player-data，与根 playerdata 限额 YAML 分开。业务数据默认保留；缺失数据参与条件可能 ERROR，不假定为 0。先初始化再比较。

## 限购与冷却

| reset | 实际规则 |
| --- | --- |
| DAILY | 服务器 JVM 时区每日零点 |
| WEEKLY | 服务器时区周一零点 |
| MONTHLY | 服务器时区每月一日零点 |
| NEVER | 永不自动重置 |
| TIMED | 首次成功起算 timedSeconds 秒；后续购买不延长窗口 |

player 为 -1 不限、0 禁购、正整数额度；server 仅可省略或 -1，全服额度未实现。规则名与 cooldown 中同名项配对，冷却为非负整数秒、成功后开始、跨重启保留、不随计数周期重置。

scope 显式相同可在同菜单多个按钮共享规则身份（共享额度与相应冷却）；不同菜单不共享。未给 scope 时使用菜单 ID/按钮 ID/规则名生成身份。已上线改这些标识或重置模式要计划迁移，不把改名当正常重置。限额按 give_item 总数量，无 give_item 时为 1；条件 FAIL 不消耗成功购买额度。

## 执行与恢复

同玩家生产操作串行准入；ClickGuard 防同一按钮重复点击。条件 → 限额/冷却预留 → 可逆状态动作（按配置顺序）→ 必要状态持久化 → 提交后副作用（按配置顺序）→ 最终收据。可逆状态与副作用分阶段，因此混写时并不保证与原列表完全交错执行；不要用 message/command 充当可逆步骤之间的探针。

delay 是当前动作前等待的 tick，后续等待；chance 默认 1，未命中跳过；return 正常结束收集并提交此前状态，不是错误回滚。限额发货不能随机或放 return 后。

失败逆序补偿已完成可逆动作；消息、声音、命令、已展示菜单不能撤回。只有确认补偿完成才称已回滚；未知状态/补偿失败保留 transactionId、阻断和恢复记录。effectsPending/最终回执失败不等于未成交；不自动重放或重复扣款。
