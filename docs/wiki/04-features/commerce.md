# 04.4 Vault 经济与买卖

[返回 Wiki 首页](../README.md) · [项目入口](../../../README.md)

> 适用：DialogCanvas 1.0.0，Paper 26.1～26.3 系列（构建范围见最终验收）；核对日期：2026-10-16。

**前置知识：** 测试服有 Vault 桥及经济提供者。

## 依赖与检查

Vault 桥负责服务接口，余额由经济插件提供。控制台和 `/api/meta` 的 provider 可核对服务发现；“未连接”不能交易。PAPI 不是经济服务，不安装 PAPI 也可正常扣款。某个余额变量能显示不证明 Vault withdraw/deposit 可用。

## 买入与出售

数量输入 key=`amount`，滑块 1～16。购买：withdraw `16 * $(amount)` → give_item `oak_log`/`$(amount)` → message 总价。出售：take_item 普通 `oak_log`/`$(amount)` → deposit `8 * $(amount)` → message。勾选确认条件为 bool 输入按字符串 `'true'` 比较。正文物品和按钮图标不生成上述动作。

预期：买 2 个扣 32；卖 2 个得 16。示例真实影响余额与背包，文档校验不会执行。金额与数量需有限且为正，物品数量必须正整数；动态输入在点击时再次校验。库存不足不充值，余额不足不发货；收取物品按完整原型匹配，只写材质匹配普通物品，改名等特殊物品不应误收。

## 额度与失败

有 give_item 的限额按成功链配置的发货总数量，多个发货项相加；无发货动作时按 1 单位。每日 32 是 32 个，不是 32 次。出售不自动返还购买额度，也没有“按出售件数限购”的独立计数表达式。

状态动作失败尝试逆序补偿，如扣款后发货失败尝试退款；补偿可能失败或结果不确定，保留恢复记录并阻止重复交易。多插件经济、背包和文件不是原子数据库事务。成功消息仅在必要状态持久化后发送；已提交后消息/PAPI/命令失败不撤销已成交状态。

先用小数量、测试余额、空背包空间验证，再逐步增大；不通过删 playerdata/交易记录“重置测试”。没有管理端自动退款/重放按钮。
