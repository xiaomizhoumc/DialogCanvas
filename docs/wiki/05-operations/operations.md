# 05.3 更新、备份、迁移与恢复

[返回 Wiki 首页](../README.md) · [项目入口](../../../README.md)

> 适用：DialogCanvas 1.0.0，Paper 26.1～26.3 系列（构建范围见最终验收）；核对日期：2026-10-16。

**前置知识：** 有服务器文件权限；知道事务状态需要核查。

## 正常更新

先记录版本 → 正常 stop → 等 Java 进程退出及保存完成 → 备份整个插件目录和经济插件所需数据 → 替换唯一 DCMenu JAR → 启动 → 检查控制台、`dcmenu editor`、list → 登录重读 → 测试少量无副作用菜单。禁止热覆盖运行中的 JAR；不使用第三方热重载器代替停服流程。

备份整个插件目录，比只保存 YAML 可靠：包括正式 JSON、手动 YAML、menu-sync、playerdata、player-data、transactions、recovery、retention-backups、config 和审计。密码哈希也是敏感配置，限制备份访问，不放公开仓库。

## 已有 YAML 迁移

旧版 `data/menus/<id>.yml` 可触发同模型一次性迁移，先完成整集合解析/引用/同名检查并保留原字节备份与回执；冲突不静默覆盖。新安装手动入口仍是插件根 `menus/`，不要拿迁移目录当常规导入入口。备份/回执路径以 [YAML 维护专题](../../../YAML_EDITING.md) 和 MenuPersistence 定义为准，不手工拼同步基线。

## 恢复分类

- 误改菜单但未保存：取消字段/撤销；关闭页面不保证内存恢复。
- 已保存菜单需回退：从备份 YAML 经校验/导入正常保存，引用仍需有效，无法绕过当前 revision。
- 文件/基线不一致：停服备份相关全套内容及日志，按已知一致备份恢复；不要仅删基线解除冲突。
- 限额归档恢复：使用 data restore 的备份 UUID，按精确状态冲突保护。
- 未决交易/补偿失败：先核对余额、背包、交易意图、限额和恢复记录；没有自动重放或一键清空记录命令。不能用菜单回退充当经济退款。

不同文件各自原子替换不等于整目录/多文件原子事务；崩溃和硬断电需保留证据，不能根据单个“已发送成功消息”推定所有落盘完成。
