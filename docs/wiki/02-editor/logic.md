# 02.4 从空白菜单建立导航与商店

[返回 Wiki 首页](../README.md) · [项目入口](../../../README.md)

> 适用：DialogCanvas 1.0.0，Paper 26.1～26.3 系列（构建范围见最终验收）；核对日期：2026-10-16。

**前置知识：** 先完成第一个菜单；商店需测试经济服务。

## 空白导航菜单完整流程

1. 按入门教程建立并保存两个多按钮菜单 `wiki_destination_a`、`wiki_destination_b`，保留新建时自带的关闭按钮。
2. “新建”，菜单标识填 `wiki_navigation_web`，标题“服务器导航”，类型“多按钮菜单”，“按钮列数”填 `2`。
3. 选第一个按钮，标签“传送说明”，点击方式选“处理点击”（`custom`）；条件满足后“添加动作”，选“打开其他菜单”，目标菜单标识填 `wiki_destination_a`。
4. 再添加按钮，标签“规则说明”，同样处理点击并打开 `wiki_destination_b`；保留/添加关闭按钮，使用“关闭菜单”。图标选已支持映射，如末影珍珠。
5. 校验、保存、重新读取，游戏 `/dcmenu open wiki_navigation_web`。目标必须已经正式存在，草稿 ID 不算存在。

常见问题：把目标标题填成 ID；目标未保存；选择“不执行操作”后期待执行 actions；菜单类型切换后遗留另一类按钮槽位。

## 空白商店完整流程

本例真实买卖橡木原木，买价 16、卖价 8。仅在测试服、测试账号执行最终点击。

1. 确认经济插件及 Vault 兼容桥已启用，控制台有经济提供者就绪信息。开发者可检查 `/api/meta` 的 `capabilities.economy.provider` 是否为实际提供者名称，不能仅看动作引擎已实现。只有桥没有经济提供者不够。
2. 新建 `wiki_shop_web`，类型“多按钮菜单”、标题“橡木原木商店”、列数 `2`；“点击后菜单如何显示”选“保持菜单打开”对应 `NONE`。
3. 加“物品展示”，材质选橡木原木，数量 `1`；这只展示。添加文字说明“买入 16/卖出 8 游戏币”。
4. 加勾选输入：key=`confirm`、标签“确认真实交易”、初始不勾选。加数字滑块：key=`amount`、起点 `1`、终点 `16`、步长 `1`、初始 `1`。
5. 添加按钮，显示文字填“购买”，“按钮点击方式”选“处理点击”。“添加条件组”选“全部满足”AND，点“添加条件”选择“比较文字”。在“要检查的内容”选择“读取菜单输入”、输入标识填 `confirm`；比较“等于”；“用来比较的内容”选择“直接填写”，填 `true`（字符串）。不要在输入标识填 `$(confirm)`。
6. 在“条件满足后做什么”依次添加动作：“扣除余额”，数额 `16 * $(amount)`；“给予物品”，物品注册名 `oak_log`、数量 `$(amount)`；“发送消息”，文本 `花费 $(16 * $(amount)) 游戏币，购买橡木原木 ×$(amount)。`。
7. 在“条件不满足时做什么”添加“发送消息”，填“请先勾选确认”。“购买数量与等待时间”点“添加规则”：“每位玩家最多购买”填 `32`，“何时重新计算”选“每天重置”，“再次操作前等待（秒）”填 `2`；启用动作后刷新。计数是发货数量，不是点击次数。
8. 复制按钮，改 ID 为 `sell`、标签“出售”；成功动作改为先收物品 `oak_log`/`$(amount)`，再增加余额 `8 * $(amount)`，再消息“出售橡木原木 ×$(amount)，获得 $(8 * $(amount)) 游戏币。”。删除复制来的购买额度规则，另设出售冷却；保留确认条件。不能仅改标签就宣称已改价格。
9. 校验，修复定位错误，保存，重新读取。游戏打开 `wiki_shop_web`；先不勾确认，预期无交易；再用少量测试余额/原木核对数量、余额、额度与消息。此处为人工操作指南，不代表本轮执行真实交易。

可对照完整 [wiki_08_shop.yml](../../../examples/wiki/menus/wiki_08_shop.yml)。已有有效字段不会因编辑其他项而自动删除；无法表达的高级配置应保留原文，经 YAML 流程修改。
