# 原版百货商店

适用：本次构建的 DialogCanvas / DCMenu，Paper 26.1.2 Build 74。

包含 787 种常用原版物品、12 个分类和 833 个菜单，分类列表每页最多展示 20 件商品。首页 ID：`vanilla_shop`。

## 安装与打开

1. 停服，备份现有 DialogCanvas 插件及菜单。
2. 将安装包的 `plugins/DialogCanvas-0.1.0.jar` 放入服务端 `plugins`，替换旧版插件。
3. 将安装包 `plugins/DialogCanvas` 内的 `data/menus`、`data/menu-sync`、`menus` 三个目录，合并到服务端同名位置。保留现有其他菜单，不要整目录替换。若已经有同名 `vanilla_shop` 或 `vs_` 菜单，先处理同名冲突，再安装。
4. 启动服务器。OP 可输入 `/dcmenu open vanilla_shop` 打开首页。

默认 `data-directory: data`。若你的 `config.yml` 修改过该值，须将安装包的 `data` 内容放入所配置的数据目录，手动编辑用的 `menus` 仍位于插件根目录。安装包不含你的账户、密码、经济余额和交易记录。

普通玩家入口：在现有快捷主菜单添加一个“打开其他菜单”按钮，目标菜单填 `vanilla_shop`。若希望直接把商店设为主菜单，在网页商店首页属性勾选“快捷打开”并保存，然后使用 `/dcmenu main` 或潜行＋交换副手。已有快捷主菜单时先取消原菜单的勾选。

首次安装请复制完整菜单集合再开服，避免分类页引用尚未安装的商品。无需逐个执行 reload。后续编辑可以使用网页，或修改对应 `menus/*.yml` 后执行 `/dcmenu reload <菜单ID>`。

## 使用方式

- 进入分类，翻页选择商品，在交易页使用购买或出售数量。
- 滑块和手动输入各有对应的购买/出售按钮；填写或拖动后点击相应按钮。数量为 0 时不交易。
- 同一商品的两种购买方式共用每人每日限额，按物品数累计；出售不会返还已用额度。每天按服务器时区零点重置。
- 出售滑块和手输上限在打开商品页时读取玩家主背包的可回收数量。没有该物品时上限为 0。成功交易后自动刷新；背包发生其他变化时可点“刷新背包库存”。
- 点击成交时会再次检查真实物品；库存减少不会导致空发钱。背包放不下时购买会回退，充值被经济插件拒绝时出售会退回物品。
- 回收只匹配普通原版物品。命名、附魔、已消耗耐久或含自定义数据的物品不算入回收数量；副手及装备栏也不算。含物品的潜影盒不回收。

## 价格与限购

原木（包括去皮原木、下界菌柄）默认买价、卖价均为 **1 游戏币/个**。树皮方块和菌核卖价为 0.5，木板卖价为 0.05，避免把原木合成为更多木制品再直接回售获利。

其余是以该基准设计的默认价格：圆石购买 0.2、铁锭 8、金锭 16、钻石 128、下界合金锭 704。不同物品有不同回收价，显示在商品悬停说明和交易页；完整价格见 `catalog.json`。常用建材每日限购较多，稀有物品和装备较少，例如钻石每日 32 个、鞘翅每日 1 个。

经济功能需要可用的 Vault / VaultUnlocked 经济提供者；小数定价需要经济插件支持两位小数。该商店直接使用经济服务判断余额，不要求 PAPI 余额占位符。

每个商品有一个 `vs_item_<原版物品ID>` 菜单。调整限购时，必须同步修改该菜单两个购买按钮的 `limit.buy.player/reset`；保留相同 `scope: daily_purchase` 才能共享额度。改变两个按钮中的经济数额可以调整买卖单价；数量字段保留原表达式引用。

## 重新生成

源码工作区运行 `node scripts/generate-vanilla-shop.mjs`，输出本目录的 JSON、YAML 及匹配的同步基线。YAML 使用兼容 YAML 1.2 的 JSON 语法，可被插件正常解析。生成命令会重写本目录的生成文件，不用于直接修改已运行的服务端。

批量覆盖价格可另建 JSON，例如：

```json
{
  "DIAMOND": { "buy": 128, "sell": 32, "dailyLimit": 16 },
  "COBBLESTONE": { "buy": 0.2, "sell": 0.03, "dailyLimit": 4096 }
}
```

然后运行 `node scripts/generate-vanilla-shop.mjs --prices <价格文件路径>`。重新打包运行 `python scripts/package-vanilla-shop.py`。

## 验证范围

测试覆盖完整商品材质与菜单跳转、JSON/YAML 同步基线、原木 1:1 定价、小数总价精度、手输数量校验、共享限购、背包匹配、库存不足、充值失败时退物品，以及卖出不恢复购买额度。网页预览不执行交易，也不等同于 Minecraft 客户端像素效果；实际客户端操作和你的经济插件组合需安装后验证。

## 成交提示更新（2026-10-15）

新版消息显示实际数量与总金额，例如“出售橡木原木 ×128，获得 128 游戏币。”、“花费 128 游戏币，购买橡木原木 ×128。”。安装包同时更新插件 JAR、菜单 JSON/YAML 和同步基线。已有商店若只换 JAR，旧消息会替换数量但仍保留“每个单价”的文字；请按正常网页保存流程修改对应交易消息，或停服备份后更新对应菜单文件及基线，不要覆盖自己改过的价格和逻辑。
